# Прежде чем сказать «доступа нет»

Фраза «у меня нет доступа» — самый дорогой ответ в этом проекте. Владелец
уже давал доступ, он это помнит, и слышать отказ ему незачем. Почти всегда
доступ есть, просто лежит не там, где искали.

**Правило: сказать «доступа нет» можно только после того, как пройдены все
семь пунктов ниже и каждый дал пусто.** В ответе тогда называть, где именно
смотрел, а не просто «нет».

## Порядок поиска

Сверху — самое дешёвое и самое частое. Не перепрыгивать.

### 1. Этот репозиторий, включая чужие ветки

Работа других сессий лежит здесь же. Именно на этом пункте был провал
22.09.2026: приложение-касса с переносом из CloudShop висело в ветке
`claude/warehouse-management-app-i7jnvr` всё время, пока шёл разговор
«доступа нет».

```bash
git fetch --all --prune
git branch -r
git ls-tree -r --name-only origin/<ветка> | grep -iE "\.(csv|json|sql|sqlite|xlsx)$"
git log --all --oneline --  '*sales*' '*seed*'
```

Смотреть не только имена файлов, но и скрипты: готовый импортёр ценнее
самих данных, он приносит свежие.

### 2. `knowledge/` — второй мозг

`knowledge/README.md`, затем заметки проекта и `Открытые вопросы.md`.
Там записано, что уже пробовали и почему отвергли.

### 3. Google Drive владельца

### 4. Соседние сессии и их артефакты

Владелец может прислать ссылку вида `claude.ai/code/session_…`.

- `mcp__Claude_Code_Remote__get_session` с этим id — покажет название,
  ветки в `session_context.sources`/`outcomes` и **список артефактов**
  в `external_metadata.artifacts`;
- артефакт читается `Artifact` с `action: "read"`; полный HTML сохраняется
  на диск, дальше его можно грепать;
- `list_sessions` — если ссылки нет, но сессия была.

Из записи сессии сразу брать **имя ветки** и возвращаться к пункту 1.

### 5. Переменные окружения и коннекторы

`env | grep -i <сервис>`, `ListConnectors`, каталог Zapier
(`discover_zapier_actions`). Пусто здесь — не повод останавливаться:
в этом проекте ключи живут не в переменных.

### 6. Публичные API самого сервиса

У WooCommerce открыт Store API (`/wp-json/wc/store/v1/...`) без
авторизации: товары, категории, сортировки. Годится, чтобы проверить
гипотезу до того, как просить пароль.

### 7. Приложение владельца — ЗАПУСТИТЬ, а не грепать

Это главный урок 22.09.2026. Артефакт-приложение я прочитал, грепнул
14 МБ бандла по названиям товаров, получил ноль и объявил, что данных
внутри нет. Вывод был неверный: **в собранном бандле данные лежат
не строками, а внутри базы SQLite, собранной в бинарный блоб.**
Грепом их не видно никогда.

Артефакт сохраняется на диск целиком и открывается локально, без входа
в claude.ai:

```js
await p.goto('file://' + путь + '/app.html', { waitUntil: 'load', timeout: 120000 });
await p.waitForTimeout(9000);          // sql.js поднимает базу не мгновенно
```

Так «WAYSTEA · склад и касса» поднялось со всеми данными владельца.
Дальше Playwright ходит по интерфейсу как человек: **Отчеты → Продажи
по товарам**, таблица снимается из DOM. Рабочий скрипт —
`bootstrap/pos_report_scrape.js`.

Приём для снятия таблицы: контейнер строк ищется как элемент с наибольшим
числом детей одинаковой высоты, затем прокручивается до конца; числовые
колонки берутся **с конца строки**, иначе разбор ломается о товары
без штрихкода или артикула.

`ArtifactData` на такое приложение отвечает, что база артефакта
не объявлена, — это правда и это **не значит**, что данных нет.

Есть и ручной путь, если интерфейс не поддался: кнопка «Скачать
резервную копию» → `waystea-<дата>.sqlite`, «Скачать в Excel».

## Когда доступа правда нет

Тогда ответ строится так, и не иначе:

1. где смотрел — списком, с результатом по каждому пункту;
2. **что именно нужно** — одна строка, имя переменной или название кнопки;
3. **где это взять** — точный путь в интерфейсе, а не «получите ключ»;
4. что уже готово к моменту, когда ключ придёт.

Просить у владельца то, что он уже давал, — ошибка. Просить расплывчато
(«дайте доступ к CloudShop») — тоже: он не обязан догадываться, что нужен
именно ключ Connect API, а не логин с паролем.

## Чего не делать

- Не отвечать «нет доступа» из первого впечатления: 404 или 401 от чужого
  API ничего не доказывает, пока не пройден пункт 1.
- Не пересказывать владельцу его же слова как возражение. Он сказал
  «данные есть» — значит, они есть, и искать надо лучше.
- Не строить обходной путь на слабых данных молча. Если считаешь по
  83 интернет-заказам вместо кассы — говорить об этом прямо в ответе.
