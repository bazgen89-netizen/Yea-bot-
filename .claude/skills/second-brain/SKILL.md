# Второй мозг

База знаний живёт в `knowledge/` — это хранилище Obsidian: markdown-заметки со
ссылками `[[...]]`, которые строят граф. Читается и в Obsidian, и на GitHub.

Заметки разложены **по проектам**: `knowledge/<проект>/`. Здесь хранится контекст
всех проектов владельца, а не только того репозитория, в котором лежит папка.

## Прочитать перед работой

1. `knowledge/README.md` — список проектов.
2. `knowledge/<проект>/Открытые вопросы.md` — что не закрыто.
3. Заметки по теме задачи.

## Новый проект

Если работа идёт над проектом, которого в `knowledge/` ещё нет:

1. Заведи папку `knowledge/<короткое-имя>/`.
2. Создай `<Имя> — обзор.md` — точка входа, со ссылками на остальные заметки
   и схемой mermaid, когда связей станет много.
3. Создай `Открытые вопросы.md`.
4. Добавь строку в таблицу проектов в `knowledge/README.md`.

Ссылки `[[...]]` ищут по имени файла, а не по пути — заметки разных проектов
можно связывать напрямую.

Там записаны не только решения, но и причины: какие гипотезы отвергнуты и почему.
Это экономит повторную диагностику.

## Записать после работы

Дописывай в существующие заметки, новую заводи только под новую область.

Что фиксировать по каждой задаче:

- **Что было сломано** — симптом, как его видит владелец.
- **Причина** — не догадка, а установленный факт. Приводи строку кода, ответ API
  или цифру из замера.
- **Чем доказано** — конкретная проверка. «Проверил» без данных бесполезно.
- **Что изменено и где** — номер сниппета, файл, настройка.
- **Свои ошибки** — неверные гипотезы, дефекты, которые пришлось чинить.
  Это самое ценное: оно не даёт повторить путь заново.

Затем обнови `knowledge/Открытые вопросы.md`.

## Правила

- **Секреты не пишутся.** Пароли, ключи API, токены — только указание, где
  они хранятся. Перед коммитом прогони поиск по добавленному.
- **Ссылки должны вести на существующие заметки.** Проверь `[[...]]`.
- **Коммить и пушь.** Контейнер эфемерный: незакоммиченное исчезает вместе с сессией.

## Проверка перед коммитом

```bash
# битые ссылки
python3 - <<'PY'
import os, re
V='knowledge'
files={os.path.splitext(f)[0] for f in os.listdir(V) if f.endswith('.md')}
for f in os.listdir(V):
    if not f.endswith('.md'): continue
    txt=re.sub(r'`[^`]*`','',open(os.path.join(V,f),encoding='utf-8').read())
    for link in re.findall(r'\[\[([^\]]+)\]\]', txt):
        if link not in files:
            print(f'БИТАЯ [[{link}]] в {f}')
PY
```

Затем `git add knowledge/ && git commit && git push`.

## Восстановление прошлых сессий

Транскрипты лежат в `/root/.claude/projects/<проект>/*.jsonl`. Если в базе знаний
есть пробел, его можно восстановить оттуда: разбирай сообщения ассистента, где
подводились итоги. Учитывай, что в транскриптах есть присланные пользователем
ключи — в заметки они попасть не должны.
