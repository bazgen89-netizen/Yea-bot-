# Недельная сводка

Цель — не таблица цифр, а короткий разбор: что изменилось и что с этим делать.

## Источники

Собирай параллельно, пропуская недоступные (не подключён — так и напиши,
не выдумывай):

1. **Shopify** — `run-analytics-query` (выручка, заказы, средний чек по дням),
   `list-orders` за период, топ товаров, `get-inventory-levels` по ходовым
   позициям.
2. **Карты** — `/reviews` бота или `StoresService`: новые отзывы, рейтинг
   2ГИС и Google, отзывы без ответа.
3. **Соцсети** — Metricool `getAnalyticsDataByMetrics`: охват, переходы,
   лучший и худший пост.
4. **Рассылки** — Mailchimp `get-analytics`: открытия, клики, отписки.
5. **Реклама** — Meta Ads: расход, CTR, стоимость покупки.

## Структура отчёта

```
Итоги недели <даты>

💰 Продажи: <выручка> (<±% к прошлой>), заказов <n>, средний чек <n>
   Топ: <товар 1>, <товар 2>
   Заканчивается: <товар> — <остаток>

⭐ Карты: рейтинг 2ГИС <n>, Google <n>; новых отзывов <n>, без ответа <n>

📱 Соцсети: охват <n> (<±%>), лучший пост — <тема>

📧 Рассылка: <кампания> — открытий <n>%, кликов <n>%

📊 Реклама: расход <n>, CPA <n>, ROAS <n>

Что делать:
1. <конкретное действие>
2. <конкретное действие>
```

## Правила

- Каждое число — с изменением к прошлому периоду, иначе оно бессмысленно.
- Максимум три рекомендации, каждая — действие («поднять цену на X»,
  «закупить Y», «ответить на 4 отзыва»), а не наблюдение.
- Плохие новости пиши первыми и прямо: упавший рейтинг, нулевой ROAS,
  товар в минусе.
- Если источник недоступен, строка остаётся с пометкой «нет доступа» —
  не заменяй пропуск оценкой.

## Регулярность

Для автоматического отчёта по понедельникам используй Routine
(`create_trigger`) с фиксированным промптом «собери недельную сводку по скилу
weekly-digest». Отдельный запуск бота на CI для этого не нужен.
