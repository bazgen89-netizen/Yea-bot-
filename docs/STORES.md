# 📍 Подключение магазинов: Яндекс Карты, 2ГИС, Google

Раздел «Магазины» показывает ваши точки в боте, следит за новыми отзывами и —
где площадка это позволяет — отвечает на них.

Доступ к площадкам идёт **по вашим ключам API**, которые вы кладёте в
переменные окружения. Ни бот, ни ассистент не заходят в ваши личные кабинеты
и не знают ваших паролей.

## Что реально умеет каждая площадка

| Возможность | Яндекс Карты | 2ГИС | Google |
|---|---|---|---|
| Карточка: адрес, телефон, график | ✅ Places API | ✅ Catalog API | ✅ Places API (New) |
| Рейтинг и число отзывов | ❌ нет в API | ✅ | ✅ |
| Тексты отзывов | ❌ только кабинет | ✅ Reviews API (отдельный ключ) | ✅ (5 шт. публично, все — через Business Profile) |
| Ответ на отзыв из бота | ❌ только кабинет | ❌ только кабинет | ✅ Business Profile API (OAuth) |
| Правка описания, сайта, телефона | ❌ только кабинет | ❌ только кабинет | ✅ Business Information API (OAuth) |
| Загрузка фото | ❌ только кабинет | ❌ только кабинет | ✅ Media API (OAuth) |

Прочерки — это ограничения самих площадок, а не бота: у Яндекса и 2ГИС нет
публичного API для управления карточкой и ответов на отзывы. Для них бот даёт
прямые ссылки в кабинет: [Яндекс Бизнес](https://yandex.ru/sprav/) и
[2ГИС для бизнеса](https://account.2gis.com/).

## Шаг 1. Ключи площадок

### Яндекс Карты — `YANDEX_MAPS_KEY` (скорее всего, не нужен)

В кабинете этот ключ называется **«API Поиска по организациям»** (он же Geosearch
API / Places API) — искать надо именно это название, а не «Яндекс Карты».
Кабинет: [yandex.ru/maps-api/console](https://yandex.ru/maps-api/console),
страница продукта: [API Поиска по организациям](https://yandex.ru/maps-api/products/geosearch-api).

⚠️ **Цена — от 195 000 ₽ в год** за 1000 запросов в сутки, бесплатного тарифа нет.
Для двух-трёх собственных точек покупать его бессмысленно: данные своих
магазинов вы и так знаете. Вместо ключа заполните блок `info` в `stores.json` —
бот подставит адрес, телефон и график оттуда и даст ссылку на настоящую карточку:

```json
"info": { "phone": "+7 900 000-00-00", "hours": "ежедневно 10:00–20:00" }
```

Id организации берётся из адреса карточки:
`https://yandex.ru/maps/org/nazvanie/**1234567890**/` — это число.

Ключ имеет смысл, только если понадобится искать чужие организации (например,
конкурентов) в большом объёме.

### 2ГИС — `TWOGIS_KEY` и `TWOGIS_REVIEWS_KEY`

1. Ключ каталога: [dev.2gis.ru](https://dev.2gis.ru/) → API Каталога → получить ключ →
   `TWOGIS_KEY`.
2. Id филиала — из адреса карточки: `https://2gis.ru/firm/**70000001006123456**`.
3. Тексты отзывов отдаёт отдельный Reviews API: ключ запрашивается у 2ГИС
   отдельно, кладётся в `TWOGIS_REVIEWS_KEY`. Без него бот покажет рейтинг и
   количество отзывов из карточки, но не их тексты.

### Google — `GOOGLE_PLACES_KEY`

1. [Google Cloud Console](https://console.cloud.google.com/) → создайте проект.
2. Включите **Places API (New)**, привяжите биллинг.
3. Создайте API-ключ, ограничьте его этим API → `GOOGLE_PLACES_KEY`.
4. `place_id` точки найдите через
   [Place ID Finder](https://developers.google.com/maps/documentation/places/web-service/place-id).

## Шаг 2. Доступ владельца Google (ответы на отзывы)

Нужен, только если хотите отвечать на отзывы прямо из бота.

1. В Google Cloud включите **My Business Account Management API** и
   **My Business Business Information API**. Доступ к Business Profile APIs
   выдаётся по заявке — форма квоты есть в
   [документации Google](https://developers.google.com/my-business/content/prereqs).
2. Создайте OAuth-клиент (тип «Desktop app»), сохраните client id и secret.
3. Получите refresh token на своей машине:

   ```bash
   python scripts/google_oauth.py --client-id ... --client-secret ...
   ```

4. Заполните `GOOGLE_GBP_CLIENT_ID`, `GOOGLE_GBP_CLIENT_SECRET`,
   `GOOGLE_GBP_REFRESH_TOKEN`.
5. Узнайте `accounts/{id}/locations/{id}` вашей точки через Account Management
   API и впишите его в `owner_id` в `stores.json`.

## Шаг 3. Реестр точек

Скопируйте `stores.example.json` в `stores.json` и заполните своими данными:

```json
{
  "stores": [
    {
      "slug": "waystea-msk",
      "name": "Waystea",
      "city": "Москва",
      "address": "ул. Примерная, 1",
      "platforms": {
        "yandex": { "id": "1234567890" },
        "2gis":   { "id": "70000001006123456" },
        "google": { "id": "ChIJ...", "owner_id": "accounts/123/locations/456" }
      }
    }
  ]
}
```

Блок `info` (`phone`, `hours`, `address`) — запасные данные: бот подставит их в
карточку любой площадки, которая не ответила или требует платного ключа.
Именно так покрывается Яндекс без покупки API организаций.

`slug` — короткий идентификатор точки внутри бота (используется в `/reply`).
Площадки перечисляются только те, где точка есть. Секретов в файле нет, его
можно хранить в репозитории; путь меняется переменной `STORES_FILE`.

## Шаг 4. Уведомления о новых отзывах

1. Узнайте id своего чата с ботом (например, через @userinfobot).
2. Задайте `ADMIN_CHAT_ID` — туда будут приходить новые отзывы.
3. При необходимости измените период опроса: `REVIEWS_POLL_INTERVAL`
   (по умолчанию 1800 секунд).

Первая проверка после запуска считается прогревочной: бот запоминает уже
существующие отзывы и не заваливает вас историей. Дальше приходят только новые.
Список виденных отзывов лежит в `REVIEWS_STATE_FILE`.

> На Render файловая система эфемерна: после передеплоя состояние обнулится и
> следующая проверка снова будет прогревочной. Чтобы уведомления переживали
> перезапуск, подключите диск Render или вынесите состояние в Redis.

## Команды бота

| Команда | Что делает | Кому |
|---|---|---|
| `/stores`, кнопка «📍 Наши магазины» | карточки всех точек со всех площадок | всем |
| `/reviews` | свежие отзывы (2ГИС, Google) | всем |
| `/reply <slug> <площадка> <id_отзыва> <текст>` | ответ на отзыв | только `ADMIN_CHAT_ID` |
| `/photo <slug> <площадка> <ссылка> [категория]` | добавить фото в карточку | только `ADMIN_CHAT_ID` |
| `/setinfo <slug> <площадка> <поле> <значение>` | правка описания/сайта/телефона | только `ADMIN_CHAT_ID` |
| `/debug` | состояние ключей и доступность площадок | всем |

Площадки: `yandex`, `2gis`, `google`. Записывать (`/reply`, `/photo`,
`/setinfo`) умеет только Google — для Яндекса и 2ГИС бот вернёт ссылку на
кабинет, потому что публичного API для этих действий у них нет.

Поля `/setinfo`: `description`, `website`, `phone`.
Категории `/photo`: `ADDITIONAL` (по умолчанию), `INTERIOR`, `EXTERIOR`,
`PRODUCT`, `FOOD_AND_DRINK`, `TEAM`, `COVER`, `PROFILE`. Ссылка должна быть
публичной и вести прямо на JPG/PNG.

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `YANDEX_MAPS_KEY` | нет | ключ Places API Яндекса |
| `TWOGIS_KEY` | нет | ключ Catalog API 2ГИС |
| `TWOGIS_REVIEWS_KEY` | нет | ключ Reviews API 2ГИС (тексты отзывов) |
| `GOOGLE_PLACES_KEY` | нет | ключ Places API (New) |
| `GOOGLE_GBP_CLIENT_ID` | нет | OAuth-клиент Business Profile |
| `GOOGLE_GBP_CLIENT_SECRET` | нет | секрет OAuth-клиента |
| `GOOGLE_GBP_REFRESH_TOKEN` | нет | refresh token владельца |
| `STORES_FILE` | нет | путь к реестру, по умолчанию `stores.json` |
| `REVIEWS_STATE_FILE` | нет | файл состояния мониторинга |
| `ADMIN_CHAT_ID` | нет | чат для уведомлений и доступа к `/reply` |
| `REVIEWS_POLL_INTERVAL` | нет | период опроса отзывов, секунды |

Без этих переменных бот работает как раньше: раздел «Магазины» просто сообщает,
что не настроен.
