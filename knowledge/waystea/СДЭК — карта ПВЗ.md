# СДЭК — карта ПВЗ

## Была за проблема

Штатный виджет выбора пункта выдачи не открывался. В консоли — `403 Invalid api key`
от `api-maps.yandex.ru/v3/`.

## Причина

Плагин требует **свой** ключ Яндекс.Карт под JS API v3. В настройках стоял
`bdcdc5b2-ad87-4f79-9953-637ec65cf882` — это плейсхолдер из поставки плагина, а не
рабочий ключ. Проверено `curl` с сервера: 403 воспроизводится вне браузера, значит
блокировщики рекламы ни при чём. В npm-сборке плагина 3.11.1 лежит тот же плейсхолдер.

## Решение

Виджет заменён на собственный, на **Leaflet + OpenStreetMap** — без ключей и оплаты.

- Сняты скрипты `cdek-widget` (607 КБ) и `cdek-map`.
- Своя модалка: список с поиском по адресу и метро + карта с метками.
- Выбор сохраняется тем же контрактом, что у штатного виджета: заполняется
  `.cdek-office-code`, вставляется `.cdek-office-info`, уходит POST на
  `official_cdek_save-office`, дёргается `update_checkout`.

Сниппет **90**. См. [[Сниппеты — реестр]].

## Подводные камни, на которых обжёгся

1. Объект `var cdek` с URL сохранения плагин вешал на хендл `cdek-widget`. Сняв виджет,
   я снёс и его — выбор не сохранялся бы. Объект выдаётся отдельно через
   `WC_AJAX::get_endpoint()`.
2. **Гонка запросов**: сохранение ПВЗ и пересчёт корзины уходили одновременно.
   Пересчёт рисует блок из сессии и, успевая первым, затирал выбор. Теперь строго
   последовательно: сохранили → пересчитали.
3. Сброс по `payment_method` обнулял выбранный пункт. Очистка привязана к реальному
   изменению адреса.

## Проверено

Заказ создаётся с `_official_cdek_office_code`, поле возвращается заполненным после
трёх пересчётов подряд.
