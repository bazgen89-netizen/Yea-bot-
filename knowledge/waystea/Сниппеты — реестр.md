## Правила

- Всё, что работает из очереди заданий или cron (например создание накладной),
  требует scope **global** — на `front-end` не загрузится.
- Порядок фильтров задаётся явно: округление на приоритете 100, сетка на 110.
- Временные диагностические сниппеты помечаются `TEMP` и деактивируются сразу после
  использования. Метод DELETE в API Code Snippets только деактивирует, не удаляет;
  `?force=true` отдаёт 500 — чистить в админке вручную.
- Одного правила мало: 22.09.2026 нашёлся забытый активным одноразовый
  сниппет с открытым наружу адресом. Поэтому **в конце каждой сессии —
  запросить список активных сниппетов и глазами сверить со списком выше**.
  Всё, чего в таблице нет, либо описывается, либо выключается.
- Сниппет, код которого не проходит проверку, не удаляется из списка, пока
  код не заменён заглушкой. Сначала `code = '// пусто'`, потом удаление.

## Второй плагин сниппетов — WPCode

Кроме Code Snippets на сайте работает **WPCode**, и часть кода живёт там.
Про него легко забыть: его записи не отдаются через REST, их не видно
ни в списке типов записей, ни в API Code Snippets.

- **14783** «Безымянный сниппет», `wpcode`, автовставка — большой файл
  на ~400 строк: вишлист, блок отзывов на карточке, правки цен, звёзды
  в каталоге. Раздел «6. ХИТЫ ПРОДАЖ» из него вырезан 22.09.2026,
  см. [[Хиты продаж]].
- **15035** — склейка дублей товаров, см. [[SEO — индексация и Яндекс]].

Код WPCode лежит в `post_content`, но исполняется из опции
`wpcode_snippets`. После правки нужно звать
`wpcode()->cache->cache_all_loaded_snippets()`. `wp_update_post` на этих
записях падает с «Содержимое, заголовок и отрывок пусты» — пишется
только через `$wpdb->update` и `clean_post_cache()`.
