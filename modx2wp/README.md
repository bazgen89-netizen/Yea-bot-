# Перенос ecopark33.ru с MODX на WordPress

Исходный сайт: **MODX Revolution 3.0.3-pl**, 54 ресурса, 6 шаблонов, 25 TV,
29 чанков, 38 сниппетов. Вёрстка своя, не покупная.

Задача — перенести сайт на WordPress **без изменения внешнего вида и адресов
страниц**: сайт SEO-нагруженный, половина «Услуг» это посадочные страницы под
поисковые запросы, терять их позиции нельзя.

## Что уже сделано

`theme/ecopark/` — тема WordPress, портированная с исходной вёрстки.
HTML, CSS и JS перенесены как есть; переписан только слой данных.

## Что во что превратилось

| MODX | WordPress |
|---|---|
| шаблон «Главная страница» | `front-page.php` |
| шаблон «Номерной фонд» | `single-cottage.php`, тип записи `cottage` |
| шаблон «Услуги» | `single-service.php`, тип записи `service` |
| шаблон «Страница событий» | `single-event.php`, тип записи `event` |
| шаблоны «Стандартная» и «Начальный» | `page.php`, обычные страницы |
| чанк `head` | `header.php` |
| чанки `footer`, `map_and_footer` | `footer.php`, `template-parts/map.php` |
| 25 TV | поля в `inc/fields.php` |
| TV типа MIGX (2 слайдера) | повторяющиеся поля, `inc/meta-boxes.php` |
| `pdoMenu`, `pdoCrumbs` | меню WordPress |
| `pdoSitemap` и ресурс `sitemap.xml` | `inc/sitemap.php`, тот же адрес |
| мета-теги из чанка `head` | `inc/seo.php` |
| `robots.txt` | `inc/robots.php` |
| `getResources` | `WP_Query` в `inc/template-tags.php` |
| `getImageList` | `eco_rows()` |
| `sldimgsize` | `eco_image_size_attr()` |
| `randomrooms` | `eco_other_cottages()` |
| `setpagerel`, `setpagerelog` | `eco_canonical_url()` |
| обработчик `/req.html` | `inc/forms.php`, адрес и формат ответа те же |
| чанк `cookieslabel` | `template-parts/cookies.php` |
| чанки `yaMetrika`, `vkPixel` | `template-parts/counters.php` |

Плагины не нужны: повторяющиеся поля есть только в платной версии ACF,
поэтому свой слой полей встроен в тему.

## Как сохранены адреса

На старом сайте схема смешанная: часть страниц папками (`/uslugi/spa/`),
часть файлами (`/contacts.html`). Штатные правила WordPress так не умеют.

Точный путь хранится у каждой записи в поле `_eco_uri`, карта
«путь → запись» лежит в опции `eco_uri_map` и разбирается в `parse_request`
(`inc/permalinks.php`). Адрес любой страницы правится в админке в блоке
«Адрес и заголовок», без правки кода.

Дополнительно:

* адрес приводится к каноническому виду 301-м редиректом, чтобы одна
  страница не открывалась и со слэшем, и без;
* старые адреса вида `/42.html` ведут на нужную страницу по сохранённому
  `_eco_modx_id`;
* произвольные редиректы можно положить в опцию `eco_redirects`
  (массив `старый путь => новый путь`).

Тема требует включённых постоянных ссылок — при «простых» WordPress отдаёт
главную вместо 404. Если они выключены, в админке висит предупреждение.

## Мета-теги, карта сайта и robots

Тема выводит `<title>`, `description`, `robots` и og-теги сама — ровно так,
как это делал чанк `head`. Заголовок идёт без хвоста «— Название сайта»:
на старом сайте его не было, а заголовки уже проиндексированы.

«Умная типографика» WordPress отключена. Она подменяет дефис на длинное
тире (`Сосновый - Коттедж` превращался в `Сосновый — Коттедж`) и портит
кавычки внутри inline-скриптов в тексте страниц.

Карта сайта отдаётся по прежнему адресу `/sitemap.xml`, а не по адресу
`/wp-sitemap.xml` от ядра: прежний уже передан в Яндекс и Google. Набор
адресов совпадает с боевым один в один, включая правило старого сайта
«страницы с флагом „скрыть в меню“ в карту не попадают».

`robots.txt` перенесён как есть — вместе с директивами `Clean-param`
для Яндекса, — плюс закрыты служебные каталоги WordPress.

Если позже поставят SEO-плагин (Yoast, Rank Math, SEOPress, All in One),
тема отдаёт всё это ему и молчит, чтобы не было двух `description`
и двух `canonical`.

## Что осталось от старого сайта без изменений

* вёрстка и стили — `assets/css/`, `assets/js/`;
* бронирование TravelLine (`TL-INT-ecopark33_2022-07-25`) — шорткод `[travelline]`;
* Яндекс.Метрика `49319104`, Top.Mail.Ru `3721594`, виджет карты, чат noya-ai;
* `assets/js/script.js` не менялся вообще: формы по-прежнему уходят
  POST-запросом на `/req.html` и ждут ответ `{"r":true}`.

## Настройки в админке

* **Настройки → Контакты** — телефон, адрес, почта, реквизиты, куда слать заявки.
* **Заявки** — все отправленные формы. Заявка сохраняется даже если письмо не
  ушло; в списке видно, доставлено письмо или нет.
* **Внешний вид → Меню** — 5 областей: верхнее, подвал, правовые ссылки и три
  колонки мобильного меню.

## Картинки контента

Файлы из `/content/` переносятся на новый сервер **по тем же путям**. Так
адреса картинок не меняются — это важно для поиска по картинкам и для
внутренних ссылок в тексте страниц. Статика самой темы при этом живёт
в `wp-content/themes/ecopark/assets/`.

## Проверено

Тема поднята на чистом WordPress, прогнан полный импорт содержимого:

* **все 46 опубликованных страниц совпали со старым сайтом полностью** —
  заголовок, описание, правило индексации, H1 и канонический адрес
  (сверка скриптом `migrate/compare.py`);
* карта сайта совпадает с боевой адрес в адрес;
* адрес с неразрывным дефисом `/uslugi/banya-po‑chyornomu/` открывается;
* страницы отдаются без единой ошибки JavaScript.

Помимо этого:

* все типы страниц отдают 200 и свой шаблон, без PHP-ошибок;
* адреса совпадают с исходными, включая `.html`;
* несуществующий адрес отдаёт 404;
* канонические редиректы работают в обе стороны;
* формы принимаются на `/req.html`, ловушка для ботов срабатывает,
  заявка сохраняется в базу;
* вся статика темы отдаётся с кодом 200;
* метабоксы полей открываются без ошибок.
