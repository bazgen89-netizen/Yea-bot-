# Перенос содержимого MODX → WordPress

Три шага. Все скрипты идемпотентны: повторный запуск обновляет, а не дублирует.

## 1. Выгрузка из MODX

Нужны данные из менеджера MODX:

```
<папка выгрузки>/
    resources/<id>.json   ресурсы           (процессор Resource/Get)
    tvs/<id>.json         значения TV       (разбор формы редактирования)
    src/chunks/<id>.json  чанки             (процессор Element/Chunk/Get)
```

Значения TV приходится снимать с формы редактирования ресурса: отдельного
процессора, который отдаёт их списком, в MODX 3 нет, а типы «изображение»,
«переключатель» и «флажок» вообще рисует ExtJS — их значения лежат
в JS-конфиге страницы, а не в HTML-полях.

## 2. Сборка

```
python3 build_bundle.py --src <папка выгрузки> --out bundle.json
```

Складывает всё в один файл: страницы в порядке «родитель раньше ребёнка»,
статические чанки как блоки и список медиафайлов.

Что происходит по дороге:

| MODX | WordPress |
|---|---|
| шаблон «Номерной фонд» | тип записи `cottage` |
| шаблон «Услуги» | тип записи `service` |
| шаблон «Страница событий» | тип записи `event` |
| остальные шаблоны | обычные страницы |
| флажок TV (`en`) | `1` |
| TV типа MIGX | массив строк повторителя |
| TV-картинка | путь от корня сайта с учётом медиаисточника |
| `sitemap_freq`, `sitemap_prio`, `index_page` | не переносятся — это работа SEO-плагина |
| `req.html`, `sitemap.xml` | не переносятся — их заменяют тема и плагин |

## 3. Импорт в WordPress

```
php import.php --wp=/путь/к/wordpress --bundle=bundle.json --dry   # посмотреть
php import.php --wp=/путь/к/wordpress --bundle=bundle.json         # выполнить
```

Тема «ЭкоПарк» должна быть уже активна — импорт опирается на её функции.

Импорт делает два прохода: сначала создаёт все записи, потом переписывает
содержимое. Иначе ссылки `[[~15]]` указывали бы на страницы, которых
в момент обработки ещё нет.

Что переписывается в тексте:

| было в MODX | стало |
|---|---|
| `[[~15]]` | постоянная ссылка страницы |
| `[[*pagetitle]]`, `[[*longtitle]]` | значение поля |
| `[[$travelline]]` | `[travelline]` |
| `[[$services]]`, `[[$links]]`, `[[$calendar]]` | одноимённые шорткоды |
| `[[$mesblock]`, `[[$otzyv]]` и другие статические чанки | `[block slug="..."]` |
| `getResources` с `nomera_anblock_2` | `[cottages]` |
| `getResources` с `events_slider_element` | `[events]` |
| `getResources` с `events_mainpage` | `[main_event]` |
| `template/...` | адрес статики темы |

Вызовы несуществующих чанков и ресурсов удаляются — ровно так же с ними
поступал сам MODX, — но каждый попадает в отчёт в конце запуска.

Дополнительно импорт назначает главную страницу и записывает редиректы:
`index.html` → `/` и `<id>.html` → текущий адрес для каждой страницы.

## 4. Медиафайлы

```
python3 fetch_media.py --bundle bundle.json --base https://ecopark33.ru/ --out ./media
```

Скачивает всё, на что ссылаются страницы и поля, сохраняя пути. Содержимое
`./media` кладётся в корень нового сайта: адреса картинок не меняются,
поэтому не теряется индексация изображений и не ломаются ссылки в текстах.

В медиабиблиотеку WordPress файлы намеренно не заливаются — иначе у каждого
поменялся бы адрес. Поля темы понимают оба варианта: и путь к файлу,
и id вложения, так что новые картинки редактор загружает уже обычным образом.
