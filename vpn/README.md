# 🛡 Свой VPN с белыми списками

VLESS + Reality (Xray) с двумя видами «белых списков»:

| Что | Где работает | Зачем |
|---|---|---|
| **Split tunnel по доменам** | на клиенте | через VPN идут только заблокированные иностранные сервисы; банки, госуслуги и локальные сайты — напрямую, со своим IP |
| **Гео-фильтр по странам** | на сервере, nftables | порт VPN отвечает только на IP из разрешённых стран; для остальных сканеров порт «закрыт» |

Ключи выдаёт Telegram-бот из этого репозитория (`/vpn_new`), либо правится
`data/users.json` руками.

> Разворачивайте только на собственном сервере и для законного использования.
> Ответственность за соблюдение местного законодательства — на владельце сервера.

## Почему именно так

- **Reality вместо обычного TLS**: соединение неотличимо от настоящего HTTPS к
  чужому популярному сайту (`REALITY_SNI`). Не нужен свой домен и сертификат,
  активное зондирование со стороны DPI получает ответ настоящего сайта.
- **Whitelist, а не «весь трафик в туннель»**: меньше нагрузки на сервер,
  местные сервисы не блокируют вас за иностранный IP, а профиль трафика
  выглядит обычнее.
- **Гео-фильтр**: сервер, отвечающий всему интернету, находят массовыми
  сканами за часы. Ограничение по странам резко сокращает эту поверхность.

## Быстрый старт

Нужен VPS вне страны с блокировками (Debian 12 / Ubuntu 22.04+), root.

```bash
git clone https://github.com/bazgen89-netizen/Yea-bot-.git /opt/vpn-src
cd /opt/vpn-src/vpn
sudo ./tools/install.sh --host <IP сервера> --countries ru,by
```

Скрипт:

1. ставит Docker, если его нет;
2. проверяет сайт-маскировку на TLS 1.3 + HTTP/2;
3. генерирует ключевую пару Reality и `short id`, кладёт их в `.env` (chmod 600);
4. собирает `config/xray-server.json` и поднимает контейнер;
5. включает гео-фильтр для указанных стран;
6. печатает `vless://`-ссылку первого ключа.

Проверить: `docker compose logs -f xray`, `nft list table inet vpn_geofilter | head`.

### Выбор сайта-маскировки (`--sni`)

Требования: настоящий сайт, TLS 1.3 + HTTP/2, **не** заблокирован в стране
пользователя, желательно в том же регионе, что и ваш сервер, и не ваш собственный.
Плохие кандидаты — сайты, которые в этой стране уже недоступны: DPI увидит
«запрещённое» имя в ClientHello.

## Клиентские конфиги с белым списком

```bash
# всё сразу: Xray, sing-box и plain-список доменов
python3 tools/gen_client_config.py --profile ru --link "vless://..." -o out/

# только AI и разработка через VPN
python3 tools/gen_client_config.py --profile ru --groups ai,dev --link "vless://..."

# с тегами geosite (нужен geosite.dat у клиента)
python3 tools/gen_client_config.py --profile ru --link "vless://..." --with-geosite
```

Профили лежат в `config/profiles/`: `ru`, `ir`, `by`, `cn`, `global`.
Каждый профиль задаёт, какие группы сервисов идут через VPN и какие локальные
домены/`geoip` остаются напрямую.

Группы сервисов — `data/services.json`: `ai`, `social`, `messengers`, `media`,
`google`, `dev`, `news`, `shops`, `privacy`. Добавить свой домен — допишите
суффикс в нужную группу, перегенерируйте конфиг.

Мобильные клиенты (v2rayNG, Streisand, Hiddify) обычно импортируют саму
`vless://`-ссылку, а правила маршрутизации задаются в их UI — сгенерированный
`proxy-domains-<профиль>.txt` можно вставить туда списком.

## Гео-фильтр

```bash
sudo ./tools/geofw.sh --countries ru,by,kz --port 443   # применить
sudo ./tools/geofw.sh --countries ru --dry-run          # показать правила
sudo ./tools/geofw.sh --flush                           # снять
```

Правила касаются только порта VPN — SSH и прочие сервисы не затрагиваются,
заблокировать себе доступ к серверу нельзя. Списки CIDR берутся с ipdeny.com и
кэшируются в `/var/cache/vpn-geofw`; обновлять раз в неделю (команду для cron
скрипт печатает в конце).

⚠️ Гео-фильтр — это защита от сканеров, а не от целевого блокирования. Он
поможет, если ваши пользователи сидят в одной-двух странах, и помешает, если
кто-то поедет в отпуск.

## Управление ключами

Через бота (`VPN_ADMINS` — ваш Telegram ID):

| Команда | Что делает |
|---|---|
| `/vpn` | показать свои ключи и инструкцию по подключению |
| `/vpn_new [название]` | выдать новый ключ (только админ) |
| `/vpn_list` | все активные ключи (только админ) |
| `/vpn_revoke <uuid>` | отозвать ключ |

Бот пишет `data/users.json` и вызывает `VPN_RELOAD_CMD` (по умолчанию
`tools/apply.sh`), который пересобирает конфиг и перезапускает контейнер.
Если бот и VPN — разные машины, подставьте в `VPN_RELOAD_CMD` ssh-обёртку.

Вручную:

```bash
# добавить пользователя
python3 - <<'PY'
import json, uuid, pathlib
p = pathlib.Path("data/users.json")
d = json.loads(p.read_text())
d["users"].append({"uuid": str(uuid.uuid4()), "label": "друг", "tg_id": None})
p.write_text(json.dumps(d, ensure_ascii=False, indent=2))
PY
./tools/apply.sh
```

Отзыв — поле `"revoked": true` у нужной записи и снова `./tools/apply.sh`.
Записи не удаляются, чтобы сохранялась история выдачи.

## Структура

```
vpn/
├── docker-compose.yml            # Xray в host-сети
├── .env.example                  # параметры сервера (реальный .env в .gitignore)
├── config/
│   ├── profiles/*.json           # страновые профили маршрутизации
│   └── xray-server.json          # генерируется, не коммитится
├── data/
│   ├── services.json             # группы иностранных сервисов
│   └── users.example.json        # шаблон списка ключей
└── tools/
    ├── install.sh                # развёртывание сервера
    ├── apply.sh                  # users.json → конфиг → рестарт
    ├── geofw.sh                  # гео-фильтр nftables
    ├── gen_server_config.py      # серверный конфиг Xray
    └── gen_client_config.py      # клиентские whitelist-конфиги
```

## Если перестало работать

| Симптом | Причина | Что делать |
|---|---|---|
| Клиент не подключается сразу после установки | гео-фильтр отрезал вашу страну | `./tools/geofw.sh --flush`, проверить, добавить страну |
| Работало и вдруг встало у всех | заблокирован IP сервера | сменить IP; Reality сам по себе IP не спасает |
| Работает, но местные сайты открываются с иностранного IP | не применён whitelist-профиль | перегенерировать клиентский конфиг |
| Xray не стартует | битый `xray-server.json` | `docker compose logs xray`, затем `./tools/apply.sh` |
| Новый ключ не работает | контейнер не перезапущен | `./tools/apply.sh` (Xray не читает конфиг на лету) |
