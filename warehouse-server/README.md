# Сервер склада

Общая база для приложения «Склад»: одни и те же товары, остатки и продажи на всех
устройствах, сотрудники с разными правами, несколько точек и открытый API для
интеграций.

> ⚠️ **В работе.** Готов фундамент: схема базы, вход по паролю, сессии устройств,
> ключи интеграций. HTTP-эндпоинты, синхронизация и Docker-сборка — следующим
> шагом. Пока запускать нечего, но всё, что написано, покрыто тестами.

## Что уже сделано

- **Схема базы** под синхронизацию: UUID вместо автоинкремента, счётчик изменений
  `seq`, мягкое удаление, остатки в разрезе точек
- **Пароли** — scrypt из стандартной библиотеки Node, без нативных зависимостей
- **Сессии устройств** — долгоживущие токены, в базе только хеш
- **Ключи интеграций** — свои права (`read` / `write`), отзыв без смены пароля
- **18 тестов** на настоящем PostgreSQL (PGlite, в памяти)

## Что осталось

- HTTP-эндпоинты: товары, приход/списание, продажи, отчёты
- Синхронизация: `push` и `pull` по номеру изменения
- Скрытие закупочных цен и прибыли от роли «продавец»
- OpenAPI-описание и страница документации
- Dockerfile и docker-compose для запуска на любом хостинге

## Устройство

```
warehouse-server/
├── src/
│   ├── db/
│   │   ├── driver.ts    интерфейс к базе
│   │   ├── pg.ts        боевой драйвер (node-postgres)
│   │   └── schema.ts    схема и миграции
│   └── auth/
│       ├── passwords.ts scrypt
│       └── tokens.ts    сессии и ключи интеграций
└── test/                тесты на PGlite
```

Тот же приём, что в мобильном приложении: весь SQL пишется против тонкого
интерфейса `SqlDb`. На проде под ним настоящий PostgreSQL, в тестах — PGlite
(PostgreSQL, собранный в WebAssembly). Один и тот же SQL, но тесты не требуют
поднятой базы.

## Ключевые решения

**Идентификаторы — UUID, а не автоинкремент.** Телефон создаёт товар и чек, ещё
не имея связи с сервером, и должен сразу знать их идентификаторы. Автоинкремент
на двух телефонах дал бы столкновения.

**У каждой строки есть `seq`** — номер в общей очереди изменений организации.
Устройство помнит последний полученный номер и просит «всё, что больше». Это
делает синхронизацию простой: не нужно сравнивать содержимое, достаточно
сравнить числа.

**Ничего не удаляется физически.** Только флаги `archived` и `deleted`. Иначе
телефон, который неделю был офлайн, никогда не узнает, что запись исчезла.

**В базе только хеши токенов.** Утечка дампа не даёт войти в чужой аккаунт.
Пароли — через scrypt (медленно, специально), токены — через SHA-256 (быстро,
потому что проверяются на каждом запросе, а перебрать 32 случайных байта нечем).
