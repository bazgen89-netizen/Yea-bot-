# Правила работы с этим проектом

## Expo меняется от версии к версии

Перед тем как писать код с любым модулем Expo, сверьтесь с документацией именно
этой версии: https://docs.expo.dev/versions/v57.0.0/ — API из статей о прошлых
SDK часто уже переименован.

## Инварианты, которые нельзя нарушать

1. **Деньги — целые копейки, количества — целые тысячные.** Ни рублей с точкой,
   ни `parseFloat` над пользовательским вводом. Разбор — только через
   `parseMoney` / `parseQty`, вывод — через `formatMoney` / `formatQty`.

2. **Остаток не хранится.** Он считается как `SUM(stock_moves.qty_delta)`.
   Любое изменение склада — это новая запись в `stock_moves`, а не `UPDATE`
   какого-нибудь поля `stock`.

3. **Изменения склада — в транзакции.** Документ и его движения появляются
   вместе либо не появляются вовсе (`db.tx`).

4. **Арифметика — в `src/domain/`.** Там нет React и нет базы. Экраны не считают
   суммы сами: иначе логику невозможно протестировать.

5. **Миграции только добавляются.** Массив `MIGRATIONS` в `src/db/schema.ts`
   дописывается в конец. Уже выпущенные миграции менять нельзя — они применены
   на телефонах пользователей.

## Просьбы хозяина программы

Всё, о чём просит Вазген, лежит в `docs/просьбы-вазгена.md`, а порядок работы
с этим списком — в `.claude/skills/задачи-вазгена/SKILL.md`. Правило короткое:
сверился со списком, выполнил целиком, проверил в собранном приложении,
отметил, сказал вслух, что осталось.
