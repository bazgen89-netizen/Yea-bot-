# CloudShop изнутри: разбор по исходникам

Задача была — разобрать `web.cloudshop.ru` от структуры до внешнего вида,
чтобы повторить его один в один. Ниже — разбор, а в конце список того, чем
наше приложение от него отличается сегодня.

## Как это добыто, и почему без входа

CloudShop — приложение на AngularJS. У таких приложений **разметка каждого
экрана лежит отдельным HTML-файлом**, и веб-сервер отдаёт эти файлы кому
угодно: они нужны браузеру до того, как человек вошёл. Логин закрывает
*данные*, а не *устройство программы*.

Поэтому доступны без единого пароля:

| Что | Откуда | Объём |
|---|---|---|
| Разметка всех экранов | `js/pages/**`, `js/components/**` | **163 файла, 852 КБ** |
| Таблица всех состояний | `js/main-b85f39022b.js` | **135 экранов** |
| Таблица стилей | `css/my-*.css`, `css/vendor-*.css` | 890 КБ |
| Словарь подписей | `locale/WAPP/ru/…` | **1475 строк** |
| Шрифт | `assets/fonts/Roboto/*.ttf` | 3 начертания |
| Описание API | `connect-api.cloudshop.ru/docs?api-docs.json` | **OpenAPI, 18 разделов** |

Повторить разбор:

```bash
node scripts/analyze-cloudshop.mjs <папка со скачанными шаблонами>
```

**Чего этим способом не получить:** данных за логином и того, как экран
выглядит с реальными числами. Но разметка, поля, колонки, кнопки, переходы,
права, размеры и цвета — здесь полнее, чем дало бы кликанье: видно и то, что
скрыто за условиями показа.

## 1. Устройство

**AngularJS 1.x + UI-Router + Semantic UI.** Отсюда следует всё остальное:

- Один `index.html`, дальше состояния и вложенные `ui-view`. Раздел, у которого
  есть подразделы, — это состояние-обёртка из одного `<ui-view>`; так,
  `card/catalog/_view.html` состоит ровно из трёх строк.
- Экраны собираются из вложенных кусков через `ng-include`. Справочник — это
  `_list.html`, который подключает `blocks/menu.html` (панель кнопок) и
  `blocks/table.html` (таблица). Форма товара — четыре отдельных блока.
- Свои директивы вместо компонентов: `catalog-filter`, `catalog-panel`,
  `doc-timeline`, `money-timeline`, `inline-filter`, `dropdown-multiple`,
  `paginator`, `with-help`, `file-drop-zone`, `gallery-popup`, `qr-code`.
- Вёрстка — Semantic UI (`ui form`, `ui table celled`, `ui menu vertical`),
  поверх неё свой `my.css`.

### Внешний вид: числа, а не впечатление

Всё из их таблицы стилей. **Ключевое: `html { font-size: 14px }`**, а не
привычные 16 — поэтому каждый `rem` на восьмую меньше, чем кажется.

| Что | Значение |
|---|---|
| Шрифт | **Roboto** (свой файл, `assets/fonts/Roboto/`), начертания 400/500/700 |
| Основной цвет текста | `#33425B` |
| Фон страницы | `#f5f5f5` |
| Заголовок `h1` | `1.9rem` = **26,6 px** |
| Заголовок `h2` | `1.6rem` = **22,4 px** |
| Заголовок дашборда | 28 px, начертание **300** |
| Пункт бокового меню | `1rem` = **14 px** |
| Вложенный пункт | `.857em` = **12 px** |
| Тело таблицы | **14 px** |
| Ссылка в строке таблицы | **15 px**, подчёркнута `rgba(0,159,218,.5)` |
| Вторая строка в ячейке | **11 px** |
| Заголовок колонки | 14 px, **700**, `text-transform: none` |
| Заголовок блока карточки | 18 px, **500** |
| Плитка отчёта | 15,5 px, значок 66 px, цвет `#ccc` |

## 2. Справочник товаров — экран, с которого всё началось

`/card/catalog/list` → `js/pages/catalog/_list.html`

Устроен так: панель кнопок сверху, таблица, постраничная навигация, форма
быстрого добавления внизу. Пустой каталог показывает не пустую таблицу, а
сообщение «Ничего не найдено» с подсказкой «Чтобы добавить товар, услугу или
комплект, нажмите…».

### Колонки таблицы — их **24**

```
☑ · Наименование · Код · Группа · Налоги · Штрих-код · Артикул · Ед. изм. ·
PLU код · Срок годности · Категория · Страна · Поставщик · Цена продажи ·
Себестоимость · Цена закупки · Маржинальность · Наценка · Создан · Скидка ·
Мин. ост. · Тип маркировки · Система налогообложения · <остаток по каждому
магазину> · Остатки
```

Почти каждая сортируется — в разметке у неё `ng-click="filter.sort.field(...)"`
и значок со стрелкой. Столько колонок одновременно не помещается, значит есть
их выбор.

**У нас 6 колонок:** Наименование, Код, Артикул, Ед. изм., Цена продажи,
Скидка, плюс магазины. Не хватает восемнадцати, и среди них важные для чайной:
**Группа, Поставщик, Себестоимость, Цена закупки, Маржинальность, Наценка,
Срок годности, Мин. ост.**

### Панель кнопок

| Кнопка | Что делает |
|---|---|
| Поиск | по наименованию, коду, артикулу |
| Показать/скрыть группы | `toggleGroup()` |
| Оценка склада | `openStockTotal()` |
| Файл для весов | `groupProducts('scales')` — выгрузка для весов |
| Удалить | `removeSelectedProducts()` — над выделенными |
| Создать товар / Создать группу / Импорт товаров | переходы |

### Фильтр

Не набор галочек, а **конструктор условий**: группы условий, объединяемые
`AND`/`OR`, а внутри — `{тип, поле, условие, значение}`. Условия:
`in`, `eq`, `lt`, `lte`, `gt`, `gte`, `range`.

Поля, по которым фильтруют: `type`, `total_stock`, `cost`, `price`,
`categories`, `expiration_date`, `min_qty`, `discount`, `created`, `updated`,
`last_sale_date_overall`, `name`.

Готовые наборы («пресеты») — это заранее собранные условия. Например
«отрицательный остаток» разворачивается в
`total_stock < 0 AND type in ['inventory']`.

**У нас** восемь готовых фильтров и сохранение своих наборов, но конструктора
условий нет — только заранее написанные восемь.

### Виды товара называются иначе

В их данных вид товара — `inventory` / `service` / `set`, а не
`product`/`service`/`set`. Значок в списке зависит от вида: `cube` у товара,
`asterisk` у услуги, `cubes` у комплекта.

## 3. Карточка товара

`js/pages/card/catalog/form/_view.html` — четыре блока плюс выбор вида.

Вид выбирается **тремя карточками** с заголовком и описанием, и только при
создании (`ng-show="!isEdit"`). Дальше идут разделы:

### Основная информация

Наименование · Код товара (с кнопкой **«Загрузить код товара»** — код можно
получить с сервера) · Штрих-код · Артикул · **GTIN** · **Тип маркировки** ·
**Подакцизный товар** · Изображение · **Категории** (несколько, «Выберите из
списка или введите новую и нажмите Enter») · Единица измерения ·
**Весовой товар** · **Дробная услуга** · **PLU код** · **Упаковка** и
«Количество в упаковке» (упаковок можно добавить несколько) ·
**Характеристики**: высота, ширина, глубина, вес · **Описание** · **Страна**

Плюс страновые поля: `ua_marking_type`, `ua_enterprise_id`, а для Эвотора —
крепость и объём тары для алкоголя.

### Цены

**Цена закупки** · **Наценка** · Цена продажи · Скидка · Налоги · НСП

И три переключателя, каждый со своим смыслом:
- «Кассир при продаже может редактировать цену»
- «На кассах товар будет продаваться по цене магазина»
- **«Установить разные цены продажи в магазинах»** — открывает цену и наценку
  на каждый магазин отдельно

### Склад

Поставщик · Минимальный остаток · **Начальный остаток** по каждому магазину ·
Срок годности · Группа · **Товар с модификациями** / **Услуга с модификациями**

Их собственные пояснения — важные, потому что объясняют модель данных:

> «Себестоимость считается по среднему и корректируется при каждой закупке
> товара или оприходовании. Чтобы она была верной, нужно указывать цену
> закупки.»

> «При изменении количества товара будут созданы документы корректировки,
> которые не влияют на себестоимость товара.»

Отсюда следует: **себестоимость у них не поле, а расчёт** — среднее по
закупкам. Поэтому её нет в каталоге через API, и поэтому она нулевая, когда
закупки заводили без цен.

### Состав комплекта

Виден только у вида «комплект»: поиск товара, а в таблице — Наименование,
Кол-во, Стоимость, Цена продажи.

### Чего нет у нас

| Их поле | У нас |
|---|---|
| Цена закупки отдельно от себестоимости | ✔ |
| Разные цены по магазинам | ✔ таблица «Магазин · Наценка · Цена продажи» |
| Модификации | ✖ |
| Состав комплекта | ✔ поиск слева, таблица справа, «Пересчитать стоимость» |
| Упаковки | ✔ несколько, «Добавить упаковку» |
| Весовой товар, дробная услуга | ✔ |
| PLU код, GTIN, маркировка, акциз | ✔ |
| Категории списком (несколько) | ✔ отдельной таблицей, в карточке — первая |
| Габариты и вес | ✔ плюс объём, как считает он |
| Страна, Поставщик, Описание | ✔ |
| Начальные остатки при заведении | ✔ документами оприходования |
| Редактирование цены кассиром | ✔ «по свободной цене» |
| Группа (папка каталога) | ✖ |
| Реквизиты Эвотора, поля UA/KZ/UZ | ✖ привязаны к их интеграциям |

Списки маркировки и налогообложения взяты его же файлами:
`data/marking-types-ru.json` (36 групп) и `data/ru_tax_system.json` (5 режимов).
Оба отдаются без входа.

## 5. Права

Восемнадцать прав, по одному на раздел, и каждое состояние объявляет своё:
`dashboard`, `catalog`, `clients`, `suppliers`, `stores`, `staff`, `accounts`,
`money`, `movements`, `sales`, `purchases`, `return_sales`, `return_purchases`,
`changes`, `registers`, `shifts`, `reports`, `integrations`.

У нас сделано: те же пять ролей, те же 18 прав, меню собирается под права.
Нет отдельного входа при запуске и экрана «Ошибка доступа».

## 6. Интеграции

Внешний API называется **Connect API**, живёт на `connect-api.cloudshop.ru/api/v4`,
ключ передаётся заголовком `X-CloudShop-API-Access-Token`. Три уровня доступа:
Readonly, RO + Orders, Owner. Описание открыто и говорит прямо: «структура
смоделирована по образцу Shopify API».

18 разделов: компания и её статистика, клиенты (чтение и запись), магазины
(чтение и запись), товары (список, один, изменённые, удалённые, категории,
теги), документы продаж, закупок, корректировок и возвратов, создание продажи.

Себестоимость отдаётся **только внутри движений по чекам**, при
`include_inventory_movements=1`, и только если у ключа есть право
`catalog.fields.cost`.

Кроме Connect API в кабинете: WooCommerce, О!Маркет, НКТ Казахстан, Сбербанк,
Эвотор.

## 7. Что делать с нашим файлом

По убыванию того, насколько это заметно в работе:

1. **Колонки справочника.** Восемнадцати не хватает. Начать с тех, что нужны
   чайной: Группа, Поставщик, Себестоимость, Цена закупки, Наценка,
   Маржинальность, Срок годности, Мин. ост. И выбор колонок — без него
   двадцать четыре не поместятся.
2. ~~**Цена закупки отдельно от себестоимости**~~ — сделано: `purchase_price`
   рядом с `cost_price`, себестоимость считается по среднему при каждом
   приходе, наценка — от цены закупки, маржа — от себестоимости.
3. ~~**Разные цены по магазинам.**~~ — сделано, `product_prices`.
4. ~~**Разделы карточки** привести к их четырём~~ — сделано: карточка идёт
   одним листом с заголовками «Основная информация», «Состав комлекта»
   (только у комплекта), «Цены», «Склад». Две колонки блоков с рамками
   убраны: у него так не выглядит ни один экран.
5. **Конструктор фильтров** вместо восьми готовых наборов.
6. **Модификации, упаковки, весовой товар** — дальше, но в карточке они на
   виду, и без них она выглядит короче оригинала.
