# Что прокликано и что осталось доделать

Приложение обойдено сценарием `scripts/audit-app.mjs`: он открывает каждый
раздел кабинета, жмёт всё, что нажимается, и записывает, куда это привело.
Ниже — что нашлось, что уже исправлено и что ещё предстоит сделать, с эталоном
из самого CloudShop.

## Откуда эталон

Кабинет CloudShop отдаёт свой словарь подписей без входа:

```
https://web.cloudshop.ru/locale/WAPP/ru/translator.cloudshop.ru   → 1475 строк
https://web.cloudshop.ru/locale/WPAPP/ru/translator.cloudshop.ru  →  453 строки (касса)
```

Поэтому в разделах ниже стоят **точные названия полей и колонок из их
программы**, а не мои догадки о том, как это могло бы называться.

---

## Исправлено

**Мобильное меню.** Одиннадцать строк были помечены «скоро», хотя экраны
давно построены: настройки компании, магазины, счета, сотрудники, кассы,
смены, тарифы, лояльность, корзина. Все включены. «Движение денег» вело в
журнал товара — теперь в свой раздел. Добавлены «Движение товара», «Отчёты»,
«Печатные формы» и «Интерфейс кассира». «Скоро» осталось только у политики
конфиденциальности и лицензии, которых действительно нет.

**Отчёты — собраны по их коду.** Из десяти плиток открывались две, остальные
молчали или уводили на Главную. Теперь набор, порядок, названия и колонки
взяты из реестра отчётов самого CloudShop: в бандле кабинета лежит
`reports.menu`, где у каждого отчёта прописаны адрес, название, значок и
подсказки к колонкам.

Их одиннадцать, и у нас теперь ровно те же одиннадцать:

| Отчёт | Их адрес | Колонки |
|---|---|---|
| Продажи по товарам | `/reports/product` | выручка, прибыль, продаж, количество, маржа, наценка |
| Продажи по категориям | `/reports/categories` | те же |
| Продажи по комплектам | `/reports/set` | выручка, продаж, средняя цена, количество |
| Продажи по дням | `/reports/day` | продаж, выручка, себестоимость, прибыль, маржа |
| Продажи по неделям | `/reports/week` | те же |
| Продажи по месяцам | `/reports/month` | те же |
| Отчёт по движению | `/reports/motion` | на начало, поступило, выбыло, на конец |
| Отчёт по агентам | `/reports/agent` | продаж, сумма, возвратов, средний чек, приход, расход |
| Финансовый отчёт | `/reports/finance` | выручка, себестоимость, прибыль, маржа, скидки |
| Отчёт по сотрудникам | `/reports/staff` | продаж, возвратов, средний чек, скидки, позиций |
| Отчёт по счетам | `/reports/accounts` | с продаж, приход, расход, остаток |

Маржа — прибыль к выручке, наценка — прибыль к себестоимости: так они и
описаны в подсказках их кода.

Два отчёта пустые, и это честно: **комплектов** в справочнике нет (товар из
нескольких других не заводится) и **сотрудников** нет — все документы заводит
владелец. Колонки у них правильные, наполнятся, когда появятся комплекты и
сотрудники.

Конструктор отчётов: «Продажи» работает, «Склад» и «Финансы» помечены
«В разработке» — ровно как у них, а не сделаны вид, что их три.

У каждого отчёта — выбор периода и выгрузка в CSV.

**Продажа не списывала остаток магазина.** Движения по чеку писались без
магазина, поэтому общий остаток менялся, а остаток точки — нет. Продажа и
возврат теперь пишут магазин: он берётся у открытой смены или передаётся
кассой. Это нашёл тест отчёта «Остатки по магазинам».

## Осталось: карточка товара

Наша карточка знает: название, артикул, штрихкод, категорию, единицу,
закупочную и розничную цену, минимальный остаток, фото. В CloudShop полей
больше — вот их точные названия:

| Поле CloudShop | Есть у нас |
|---|---|
| Наименование, Артикул, Штрих-код, Код товара | код товара — нет |
| Категория | да |
| Единица измерения | да |
| Цена, закупка · Цена, продажа | да |
| **Наценка** | нет |
| **НДС** | нет |
| Минимальный остаток | да |
| Изображение / Фотография | да |
| **Цены и скидки** — разные цены продажи в разных магазинах | нет |
| **Товар с модификациями** | нет |
| **Комплект** и «Состав комплекта» | нет |
| **Услуга** — «продукт, не имеющий остатка на складе» | нет |
| **Изменения товара** — история правок карточки | нет |
| **История движения** по товару | нет частично: движения есть, экрана нет |
| Генерация штрих-кодов | нет |
| Ценники: «Ценник 3х2 см», «Конструктор ценников» | нет |

Три вида товара, как их описывает сам CloudShop:

- обычный — «продукт, имеющий остаток, который необходимо восполнять»
- услуга — «продукт, не имеющий остатка на складе»
- комплект — «продукт, состоящий из нескольких других»

**Что делать:** довести карточку до этого набора и разделить создание на три
вида. Самое заметное для работы чайной — модификации (один чай, разные
фасовки) и разные цены по магазинам.

## Осталось: журнал движения товара

Сейчас журнал показывает документ, время, позиции, сумму, оплаченные,
отправителя, получателя, автора. В CloudShop к этому есть:

- **Статусы документа**: «Документ проведён» / «Документ не проведён»,
  «Документ оплачен» / «Документ не оплачен» — у нас все документы всегда
  проведены, отложенных нет
- **Редактирование документа** и отметка «Документ был отредактирован»
- **Восстановление** удалённого документа из корзины
- Фильтры: по дате, статусу, оплате, типу — у нас кнопки есть, но не работают
- **Опись** (инвентаризация) как отдельный вид документа

**Что делать:** сначала фильтры — кнопки уже нарисованы и молчат, это худший
вид недоделки. Потом открытие документа на просмотр и правку.

## Осталось: создание товара

Экран создания повторяет карточку, поэтому доделывается вместе с ней.
Отдельно нужно: выбор вида (товар / услуга / комплект), генерация штрихкода,
внесение остатков сразу при создании («Внести остатки» в CloudShop).

## Осталось: мелочи, найденные обходом

- Кнопки «Фильтр», «дата», «статус», «оплата», «тип» над таблицами не работают
  ни в одном журнале — нарисованы, но приглушены
- «Действия» над каталогом (массовые операции) не работает
- «Импорт товаров» не работает
- Пагинация каталога: страницы листаются, но выбор строки открывает карточку
  не всегда

## Как перепроверить

```bash
npm run web:build
node scripts/audit-app.mjs        # обход кабинета и телефона
node scripts/audit-cashier-menu.mjs   # меню кассира
```

Разбор ложится в `dist/audit/`. Если после правки таблица разойдётся с этим
документом — врёт документ, и его надо переписать по факту, а не наоборот.
